# Supervised-local operator boundary

This runbook describes the proven supervised-local substrate only. It is not
the acceptance procedure for the frozen named-role lifecycle.

Use the trusted Pilot controls to register a project, create and queue a local
task, start the reviewed Runtime under explicit operator supervision, and
inspect the read-only Pilot UI. Treat SQLite/Pilot as lifecycle authority and
Runtime as execution observation.

When reviewing a run, distinguish:

- expected dispatch from actual retained execution evidence;
- role packet content from host-observed execution;
- workspace HEAD from accepted HEAD;
- dirty/clean status and changed paths from semantic acceptance; and
- current implementation from tested and live-proven behavior.

Do not infer a role execution from a role name, policy file, PM prose, packet,
UI row, or expected sequence. Do not manually edit lifecycle state.

The current supervised path does not prove unattended credential isolation,
the canonical fresh-specialist lifecycle, publication, or merge. The parent
harness defines the target sequence and remains the only lifecycle benchmark.
